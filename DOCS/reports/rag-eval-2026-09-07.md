## Lecture
- Hit rate @k = proportion de questions où le document attendu apparaît dans le top-k.
- Un hit rate bas peut venir du chunking (1 chunk = 1 document, pas de découpage fin), du modèle d'embedding, ou d'un corpus encore trop petit pour discriminer.

## Conditions du run

- **Store** : `pgvector` 0.8.0 (extension compilée sur `postgres:16`), table `documents`,
  distance cosinus (`embedding <=> query`), `ORDER BY distance LIMIT k`.
- **Embeddings** : `text-embedding-3-small` (1536 dim), OpenAI.
- **Corpus** : 5 documents `sessions/*.md` ingérés par `backend/scripts/ingest_rag.py`
  (Redis `emails_structured` vide sur cet environnement → 0 synthèse e-mail).
- **Réserve** : avec k=5 et un corpus de 5 documents, « @5 » est trivialement 100 %.
  Le signal réel ici est le **rang 1 pour les 5 questions** : le bon document est
  systématiquement le plus proche, pas seulement présent. À rejouer sur un corpus
  plus large (synthèses e-mails réelles + plus de sessions) pour un chiffre discriminant.
